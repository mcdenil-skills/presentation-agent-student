# Формат текста под слайды

Финальный текст хранится в обычном UTF-8 файле. Один блок `===SLIDE===` равен одному слайду.

## Базовый формат

```text
===SLIDE===
ТИП: текст
ЗАГОЛОВОК: Одна законченная мысль
ТЕКСТ:
Первое предложение объясняет смысл.
Второе показывает следствие или следующий шаг.
ВИЗУАЛ: человек проверяет результат на ноутбуке, без текста внутри изображения
```

Обязательные правила:

- `===SLIDE===` стоит на отдельной строке перед каждым слайдом;
- имена полей пишутся заглавными буквами;
- каждое предложение в `ТЕКСТ:` начинается с новой строки;
- `ВИЗУАЛ:` содержит бриф для дизайна и не попадает в видимый текст;
- один слайд несёт одну законченную мысль.

## Слайд как короткая страница

Слайд должен быть понятен без звука. Не используйте телеграфные обрубки и набор существительных.

Плохо:

```text
Опыт. Скорость. Результат.
```

Лучше:

```text
Скорость появляется не от количества инструментов.
Она появляется, когда у каждого шага есть понятный результат и проверка.
```

Заголовок содержит вывод, а не рубрику «Проблема», «Решение» или «Итог».

## Поля

| Поле | Назначение |
|---|---|
| `ТИП:` | выбор раскладки |
| `ЗАГОЛОВОК:` | главная мысль |
| `ТЕКСТ:` | видимый текст слайда |
| `ПРОМПТ:` | копируемый запрос или команда |
| `ВИЗУАЛ:` | бриф дизайнеру или пометка демонстрации |
| `НОМЕР_УРОКА:` | подпись на обложке урока |
| `ПРИЗЫВ:` | короткое действие для живого вебинара |

## Типы

- `титульный` - начало материала или раздела;
- `текст` / `контент` - основная мысль;
- `фото` - мысль с реальным изображением;
- `промпт` / `команда` - копируемый блок;
- `чат` - интерактив живого вебинара;
- `бонус` - бонус и открытая петля вебинара;
- `cta` - действие;
- `заключение` - финальный вывод.

В записанном уроке тип `чат` не используется.

## Командный слайд

```text
===SLIDE===
ТИП: команда
ЗАГОЛОВОК: Сначала проверяем окружение
ТЕКСТ:
Эта команда показывает версию Python и ничего не меняет в системе.
ПРОМПТ:
python3 --version
```

- Команда проверена вживую.
- Несколько CLI-команд разнесены по разным слайдам.
- Указано, куда её вставить и какой результат ожидать.
- Многострочный запрос обычным языком может оставаться одним блоком.

## Демонстрация

Для реального экрана используйте:

```text
ВИЗУАЛ: [ДЕМО: открыть готовую страницу и проверить форму]
```

Демо не заменяется стоковой фотографией. Кадр должен показывать именно проверяемое действие или результат.

## Объём

Точные лимиты зависят от собственного шаблона. До калибровки используйте консервативный ориентир:

| Тип | Ориентир |
|---|---|
| текст без фото | до 60 слов |
| текст с фото | до 40 слов |
| пояснение к команде | до 35 слов |
| заголовок | до 55 символов |

После подключения своего дизайна отрендерите тестовые слайды и запишите реальные лимиты раскладок в библиотеку доноров.

## Цветовой акцент

Фрагмент заголовка в `[[...]]` может получить цветовой акцент при сборке:

```text
ЗАГОЛОВОК: Сначала проверяем [[потом публикуем]]
```

Цвет задаётся в `tools/converters/text_styling.py`. Не используйте акцент, пока не выбрали собственную палитру.

## Проверка до сборки

```bash
tools/venv/bin/python tools/check_slides.py path/to/SLIDES.txt
```

Скрипт ловит переполнение, служебные маркеры, вероятные обрубки, повторы и несколько CLI-команд в одном `ПРОМПТ:`.

## Google Slides

### Простой конвертер

```bash
tools/converters/convert_google.sh "path/to/SLIDES.txt" "Название"
```

Перед запуском настройте собственный `oauth_client.json` и `config.json` по `INSTALL.md`.

### Сборка из собственного дизайна

1. Снимите палитру раскладок со своей презентации через `template_inventory.py`.
2. Подготовьте `knowledge/design/layout-library.json` и `rhythm-pattern.json` по `knowledge/design/README.md`.
3. Создайте план через `layout_director.py`.
4. Подберите изображения через `source_images.py`.
5. Примените план к копии через `apply_edits.py`.
6. Отрендерите результат через `render_slides.py` и посмотрите все PNG.

Оригинал презентации не изменяется. До сборки весь текст должен быть согласован единым потоком.

## Финальная проверка

- Нет повторов между соседними слайдами.
- Нет служебных `===`, `[[` или имён полей на слайде.
- Текст не обрезан.
- Фото не перекрывает текст.
- У каждого CTA одно понятное действие.
- Команды копируются без ручного исправления.
