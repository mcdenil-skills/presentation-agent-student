# Онбординг новой работы

Мастер запускается только для новой или неясной задачи. На точный запрос и «продолжи» отвечайте действием, а не повторным интервью.

## Шаг 1. Откуда начинаем

Предложите четыре варианта:

1. Есть готовая презентация и нужно сохранить дизайн.
2. Собираем с нуля.
3. Сначала изучаем аудиторию.
4. Нужна точечная задача.

## Шаг 2. Тип материала

- Вебинар - продающее выступление.
- Урок - записанное обучение.

Если тип уже назван, не переспрашивайте.

## Шаг 3. Гейт аудитории

До контента проверьте `knowledge/audience/`:

- есть ли свежий портрет;
- есть ли обезличенный банк дословных фраз;
- совпадает ли аудитория с текущей темой и оффером.

Если данных нет, предложите один из источников: анкета, интервью, комментарии, рассказ владельца или разрешённая выгрузка. Владелец может сознательно пропустить этап, но риск фиксируется.

## Шаг 4. Бриф

Для вебинара соберите формат, место в серии, температуру аудитории, тему, действие, оффер, цену, дату и реальное ограничение.

Для урока соберите тему, навык, источник техники, место в серии, уровень, проверяемый результат и дату.

## Шаг 5. Чекпоинт

Покажите бриф одним компактным блоком:

```text
Что делаем
Для кого
Какой результат
Что уже есть
Чего не хватает
Следующая фаза
```

Дальше двигайтесь только после подтверждения.

## Продолжение с прошлого раза

Если пользователь пишет «продолжи»:

1. проверьте `git status` и последние коммиты;
2. прочитайте последний дневник и `_progress.md`, если он есть;
3. назовите точку продолжения;
4. выполните следующий незавершённый шаг.

Не запускайте мастер заново.
